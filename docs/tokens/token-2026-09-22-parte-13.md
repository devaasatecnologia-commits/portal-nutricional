## 🗺️ ARQUITETURA DE ROTEAMENTO LOCAL

### ⚠️ O `config.js` usa roteamento via `index.php?api_route=`

**Como funciona:**

1. `portal/assets/js/config.js`:
   ```javascript
   window.API_URL = isLocal
       ? window.location.origin + appBase + '/index.php?api_route='
       : 'https://api.nutricionalbr.com/v1';
   ```

2. **No local**, `window.API_URL` vira:
   ```
   http://localhost:8080/index.php?api_route=
   ```

3. `index.php` da raiz lê `$_GET['api_route']`, prefixa com `/v1`, encaminha pro Slim

### ⚠️ Diferença crítica
- ❌ URL direta `/API/v1/frota/cobli/status` → **404**
- ✅ URL via gateway `/index.php?api_route=frota/cobli/status` → **200**

### ⚠️ Como testar endpoints no Console

## 🧪 LIÇÕES APRENDIDAS (sessão 2026-09-22 parte 13)

**126. Sobrescrever função com nome ambíguo quebra chamadas existentes**
`gerarBadgeCobli(item)` era usada na coluna "Cobli" para mostrar **status**, e o Bloco 6.5 reescreveu ela para mostrar **score**. Regra: nunca sobrescrever função com nome genérico. Ou renomeia (`gerarBadgeStatusCobli` + `gerarBadgeScoreCobli`), ou cria função nova e ajusta todos os chamadores.

**127. Antes de substituir uma função, rodar `Select-String` pra achar todos os chamadores**
```powershell
Select-String -Path "portal/modules/frota/assets/gestao-cargas.js" -Pattern "gerarBadgeCobli"
```
Isso teria revelado os 2 pontos de chamada e evitado a duplicação.

**128. Cache de dados ≠ cache de metadados**
O `carregarAbaEficiencia` tinha cache de `dados[dim]` mas esqueceu de garantir que o **cache do score Cobli** estivesse carregado. Regra: cada fonte de dados tem seu próprio ciclo de vida de cache, e o orquestrador precisa garantir **todos** antes de renderizar.

**129. Sempre conferir a contagem de `<th>` vs `<td>`**
A tabela tinha 10 `<th>` e renderizava 11 `<td>`. Isso não dá erro de console, mas quebra o layout visualmente. Adicionar uma verificação de sanidade.

**130. Estado do CSS e do JS devem ser documentados juntos**
Restaurar o CSS mas manter o JS parcialmente modificado cria um estado "torto". Sempre inventariar o que está em cada arquivo antes de aplicar o próximo bloco.

**131. Quando o mesmo item aparece em duas colunas, verificar se a função de render foi sobrescrita**
Sintoma clássico: duas `<td>` com markup idêntico. Rastrear qual função gera cada `<td>`.

**132. `colspan=11` num `<table>` com 10 `<th>` = bug de layout**

**133. Cache de UI ≠ cache de API**

**134. Renomear função é mais seguro que sobrescrever**

**135. CSS e JS precisam ser aplicados na mesma sessão quando formam um par**
