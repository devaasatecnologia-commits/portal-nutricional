🧪 LIÇÕES APRENDIDAS (sessão 2026-09-25 parte 3)
========================================

71. entity_id no cache ≠ motorista_id da frota
    O cache do Cobli usa UUID do próprio Cobli como entity_id.
    Qualquer JOIN com tabelas da frota passa obrigatoriamente por
    frota_cobli_motorista. Sem isso, a query retorna vazio silenciosamente.

72. SUM de snapshots com períodos sobrepostos infla o total
    Cache do Cobli reinsere o mesmo período a cada sincronização.
    SUM(km_rodados) soma 4× o mesmo valor se houver 4 snapshots.
    SEMPRE usar ORDER BY atualizado_em DESC LIMIT 1 para pegar o
    snapshot mais recente — ou filtrar por janela específica.

73. Fallback PHP para campos opcionais de API externa
    Cobli não expõe average_speed_in_kmh no payload do ranking.
    Cálculo PHP (km / (tempo/60)) resolve sem depender da API.

74. Ranking anônimo: RANK() OVER + COUNT(*) OVER () na mesma query
    Garante consistência atômica entre posição e total.
    Duas queries separadas podem pegar snapshots diferentes.

75. Cache PHP com TTL curto exige Remove-Item antes de validar patches
    Sempre que ajustar o backend de um método cacheado, limpar os
    arquivos antes:
    Get-ChildItem $env:TEMP -Filter "cobli_score_motorista_*.json" | Remove-Item -Force

76. rank do cache nem sempre é RANK() do SQL
    rank que a Cobli retorna é dela; RANK() OVER do SQL é o seu.
    Decidimos usar o segundo (Opção B) para garantir consistência.
    Documentar essa escolha quando ambos existirem.

77. node --check silencioso ≠ código correto
    Só valida sintaxe. Não valida se uma função está exposta em
    window nem se o id referenciado existe. As lições 67/68/69
    cobrem o resto do ciclo.

78. Integração externa precisa ser EXECUTADA, não só codificada
    O vincularMotoristasAuto() existia desde 2026-09-22 mas nunca
    rodou. O sintoma (score nulo) parecia bug de código, era dado
    ausente. SEMPRE rodar a sincronização após implementar.

79. console.table + check object é o padrão de validação end-to-end
    21 assertions em um só bloco, resultado binário (true/false por
    linha), feedback visual (✅ verde / ❌ vermelho). Reutilizar em
    todo pacote daqui pra frente.

80. Ordem de declaração de let vs. boot no IIFE
    Em IIFEs longos (5000 linhas), é fácil adicionar let no meio do
    arquivo e usá-la no boot que está mais acima. Isso quebra com
    "Cannot access X before initialization" (temporal dead zone).
    REGRA: todo estado (let/const) que é lido em runtime pelo boot
    ou por handlers registrados no boot deve ser declarado no TOPO
    do IIFE.

81. PDO + PostgreSQL NUMERIC vira string no JSON
    json_encode() em PHP serializa NUMERIC como string, e o typeof
    === 'number' do JS falha silenciosamente. Não é bug do SQL nem
    do PHP — é desserialização. (float)$valor na borda da API resolve.

82. Normalizar na borda da API ≠ normalizar no frontend
    Fazer as duas coisas:
    - Camada 1 (JS): paraNumero() como defesa em profundidade
    - Camada 2 (backend): (float) antes de devolver o JSON

83. (float)'' retorna 0.0 (não null)
    Sempre checar === null || === '' ? null : (float)$valor.
    Senão coordenada vazia vira (0,0), ponto válido no oceano Atlântico.

84. array_key_exists vs isset quando o valor pode ser null
    isset retorna false para null e a normalização não roda.
    array_key_exists retorna true para null e é o correto aqui.

85. Chip de distância calculando 204 km NÃO é bug se o motorista
    está longe do cliente. Contexto importa. Não esconder o chip
    quando o valor é grande; o motorista precisa saber.

86. Um bug de tipo pode quebrar N lugares silenciosamente
    typeof item.latitude === 'number' quebrado afetava mapa + chip
    + next-stop-distance. Ficou visível só quando o novo feature
    (M4) dependeu dele.

87. Regex de validação precisa de âncora
    /~[\d]+(min|h)/ sem ^ e $ casa "1min" dentro de "~1min" mas
    também dentro de "abc1minxyz". Se o texto vier corrompido, o
    teste passa falsamente. Para validação de presença, ancora
    com /^~\d+\s?(min|h)/ — cobre "~8 min", "~1h", "~1h 15min".
    (Lição preventiva: o teste atual passou porque o dado estava
    correto, mas o regex é frágil.)

88. Teste com dados reais ≠ teste com dados mockados
    O chip mostrou 204,2 km no teste local porque o "motorista"
    estava em Criciúma e o cliente em Floripa. Em produção, o
    motorista em campo verá 3 km, 12 km, etc. Sempre considerar
    que o ambiente de teste (PC em casa) ≠ ambiente real (motorista
    em campo com GPS).

89. Bump do SW é obrigatório a cada mudança em JS/CSS/HTML
    do app shell
    O SW usa ignoreSearch: true, então ?v= no PHP NÃO invalida o
    cache. Sempre bumpar CACHE_NAME e limpar o cache do navegador
    antes de testar. Lição 66 do token anterior reforça isso.

90. Deploy FTP — nunca subir .env
    Antes de qualquer upload, confirmar que o .env de produção
    NÃO será sobrescrito pelo local. Fazer backup remoto dos
    arquivos que serão substituídos.
