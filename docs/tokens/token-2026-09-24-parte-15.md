1. **Toda alteração em método/função: entregar COMPLETO**, nunca fragmento.
2. **Sempre validar com `php -l`** após editar PHP.
3. **Sempre testar via `curl.exe`** (console) ou diretamente no terminal.
4. **Metodologia do Padrão Ouro:** Implementação → Validação → Documentação.
5. **Backup antes de substituir** qualquer método.
6. **Registrar lições aprendidas** neste token ao final da sessão.
7. **NUNCA usar `&&` ou `&` no PowerShell 5.1** — usar `;`
8. **SEMPRE usar `curl.exe`** (com .exe) — o `curl` sem é alias do PowerShell
9. **SEMPRE salvar JSON de teste sem BOM** — usar `[System.IO.File]::WriteAllText` com `UTF8Encoding($false)`
10. **SEMPRE reiniciar Apache após alterar `api.php` ou Controllers** — PHP-FPM mantém o código em memória
11. **AO MUDAR MÉTODO: entregar arquivo COMPLETO (não fragmento)** — sem `...` ou `// resto igual`
12. **Verificar com `Select-String` se o método existe ANTES de testar** — `php -l` não detecta método faltante

🧪 LIÇÕES APRENDIDAS (sessão 2026-09-23 parte 15)
#199 — Antes de assumir "bug nosso", verificar se o backend está devolvendo vazio por escolha da API externa.
O campo rows_cruas: 0 (que mede o payload cru da Cobli) foi a chave para descobrir que a Cobli simplesmente não devolveu drivers de setembro. Sem essa métrica no response, iríamos caçar bug no lugar errado por horas.

#200 — Não existe "bug de ? duplo" no fetch do navegador.
Quando testamos via curl.exe com %26 no meio da URL, o gateway do index.php decodifica errado. Mas o fetch do navegador monta a URL corretamente. Testar sempre no Console do navegador antes de concluir que a URL está errada.

#201 — Ao testar rota via gateway com múltiplos parâmetros, usar & a partir do segundo.
/index.php?api_route=frota/xxx?mes=9&ano=2026 → o ? do meio quebra. Correto: /index.php?api_route=frota/xxx&mes=9&ano=2026.

#202 — Cobli tem 2 produtos por entidade: product_type = TELEMETRY | CAM | CAM_PRO.
A consolidação por pesoProductType (TELEMETRY > CAM > CAM_PRO) já estava correta no rankingSeguranca. Não precisou mexer.

#203 — Payload da Cobli é driver OU vehicle, nunca os dois.
Para motoristas, row.driver = { id, name } e row.vehicle = null. Para veículos, row.driver = null e row.vehicle = { id, license_plate, brand, model, ... } sem name.

#204 — Sempre usar license_plate como fallback de vehicle.name.
Sem isso, entity_nome fica vazio pra 100% dos veículos. O erro passou batido porque motoristas têm name e nunca foram testados.

#205 — Cobli calcula DRIVER e VEHICLE em jobs separados (latência diferente).
Screenshot do Cobli: Última att.: 22/09 19:54 pra driver, 23/09 00:17 pra vehicle. Nosso rows_cruas: 0 pra DRIVER em setembro confirma que o job deles para drivers ainda não rodou. Não é bug nosso.

#206 — Cache JS de 5min + cache backend de 1h + cache SQL por período — 3 camadas.
Sempre invalidar as 3 ao trocar de mês. scoreCobliState.ultimaCarga = 0 é o gatilho.

#207 — entity_id no nosso schema é o UUID da Cobli, não o ID interno.
Cruzar por item.cobli_driver_id (UUID) e não por item.id (ID interno). Foi um bug corrigido no Bloco 6.5 v2.
