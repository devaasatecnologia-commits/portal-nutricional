🧪 LIÇÕES APRENDIDAS (novas desta sessão)
#216 — Set-Content -Encoding UTF8 no PowerShell 5.1 SEMPRE adiciona BOM.

Isso quebra PHP com Namespace declaration statement has to be the very first statement.

Sempre usar:

powershell
[System.IO.File]::WriteAllText($path, $conteudo, (New-Object System.Text.UTF8Encoding($false)))
Ou remover BOM depois:

powershell
$bytes = [System.IO.File]::ReadAllBytes($path)
if ($bytes[0] -eq 0xEF -and $bytes[1] -eq 0xBB -and $bytes[2] -eq 0xBF) {
    [System.IO.File]::WriteAllBytes($path, $bytes[3..($bytes.Length-1)])
}
#217 — JwtMiddleware deve manter $handler->handle() FORA do try/catch.

O catch genérico que envolve $handler->handle() transforma qualquer exceção do Controller (PDOException, TypeError, etc) em 401 "Token inválido" — mascarando o erro real. Fix: só o JWT::decode + validação de user ativo ficam dentro do try.

#218 — Health check endpoint é público e deve estar em $publicRoutes do JwtMiddleware.

Ao criar o HealthController, adicionar /v1/frota/health no array $publicRoutes — senão o próprio health check exige token e nunca funciona como monitoramento.

#219 — json_encode() sem JSON_UNESCAPED_UNICODE gera \u00e1 em vez de á.

Não é bug, mas polui a leitura. Usar JSON_UNESCAPED_UNICODE | JSON_UNESCAPED_SLASHES para UTF-8 legível.

#220 — Health check deve SEMPRE responder 200, com status interno no body.

Se o health devolvesse 500 quando a Cobli cai, o UptimeRobot dispararia alerta falso-positivo: a API está no ar, só a dependência caiu. Regra: devolver HTTP 200 sempre; o campo status (ok/degraded/down) informa o estado.

#221 — Cache de health check em arquivo (sys_get_temp_dir()) é suficiente.

Não precisa de Redis nem tabela. file_put_contents com TTL por filemtime resolve. Padrão que já usamos no getCobliScoreMotorista. Reutilizar.

#222 — file_get_contents com offset/length evita ler arquivo grande inteiro.

No getSwVersion(), lê só 1000 bytes iniciais do service-worker.js. Suficiente para pegar CACHE_NAME. Barato e rápido.

#223 — @file_put_contents silencioso com error_log separado.

Cache best-effort não pode quebrar o endpoint. Usar @ e logar só em caso de erro real. Observação: essa lição virou problema na Fase 1.5 — o @ está mascarando falha silenciosa. Próxima sessão: substituir por error_log temporário para diagnosticar se o arquivo está sendo criado.

#224 — UptimeRobot grátis só permite 5min de intervalo (não 1min).

Para 1min, precisa do plano pago. 5min grátis já cobre bem a operação. Ajustar expectativa: "detecção de queda em ~5min", não 1min.
