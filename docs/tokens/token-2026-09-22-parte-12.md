## 🗺️ ARQUITETURA DE ROTEAMENTO LOCAL (APRENDIZADO CRÍTICO)

### ⚠️ O `config.js` usa um sistema de roteamento via `index.php?api_route=`

**Como funciona:**

1. `portal/assets/js/config.js` (linha 17-19):
   ```javascript
   window.API_URL = isLocal
       ? window.location.origin + appBase + '/index.php?api_route='
       : 'https://api.nutricionalbr.com/v1';
   ```

2. **No local**, `window.API_URL` vira:
   ```
   http://localhost:8080/index.php?api_route=
   ```
   (não é `/API` nem `/v1` — é uma URL com query string)

3. `index.php` da raiz:
   - Lê `$_GET['api_route']`
   - Se não começa com `/v1`, prefixa com `/v1`
   - Reescreve `$_SERVER['REQUEST_URI']`
   - Encaminha para `v1/public/index.php` (Slim)

### ⚠️ Diferença crítica
- ❌ URL direta `/API/v1/frota/cobli/status` → **404** (não passa pelo gateway)
- ✅ URL via gateway `/index.php?api_route=frota/cobli/status` → **200**

### ⚠️ Isso afeta todos os JS que montam URL
- O `CONFIG.API_BASE` no `gestao-cargas.js` faz:
  ```javascript
  const apiUrl = window.API_URL || '/';
  API_BASE: apiUrl + (apiUrl.endsWith('/') || apiUrl.endsWith('=') ? '' : '/') + 'frota'
  ```
- Resultado: `http://localhost:8080/index.php?api_route=frota`

### ⚠️ Como testar endpoints no Console
Sempre via `/index.php?api_route=frota/...`:
```javascript
const token = localStorage.getItem('authToken');
const r = await fetch('/index.php?api_route=frota/cobli/status', {
    headers: { 'Authorization': 'Bearer ' + token }
});
console.log(r.status, await r.json());
```

**URLs `/API/v1/...` OU `/v1/...` NÃO FUNCIONAM no navegador local** — só o gateway funciona.

## ⏳ OTIMIZAÇÕES PENDENTES (registradas na sessão parte 12)

**Contexto:** Ao abrir a área de gestão, especialmente o Mapa → Ao Vivo, demora **2-5s**. Isso é **aceitável** mas vale otimizar.

**Gargalo:** `CobliController::posicoesFrota()` faz **18 chamadas HTTP em série** para `api.cobli.co` (uma por veículo vinculado). Cada chamada depende da latência de rede entre o servidor e a Cobli.

### Otimização 1 — Cache de 30s em `posicoesFrota()`
- **Onde:** `CobliController::posicoesFrota()`
- **O que fazer:** antes de chamar `api.cobli.co`, verificar se há posição em `frota_cobli_posicao` dos últimos 30s
- **Impacto:** reduz de 18 chamadas HTTP → 0-2 na maioria dos casos
- **Prioridade:** média

### Otimização 2 — Chamadas paralelas com `curl_multi` em `CobliService`
- **Onde:** `CobliService::buscarDispositivo()` (ou novo método `buscarVariosDispositivos()`)
- **O que fazer:** usar `curl_multi_init()` + `curl_multi_add_handle()` para fazer 18 chamadas em paralelo
- **Impacto:** reduz de 18×latência → 1×latência
- **Prioridade:** média

### Otimização 3 — Configurar webhook Cobli (item 4 do roadmap)
- **Onde:** `frota_configuracao.cobli_webhook_secret`
- **O que fazer:** gerar um secret, salvar em `frota_configuracao`, configurar no painel da Cobli
- **Endpoint já existe:** `POST /v1/frota/cobli/webhook` (público, autenticado via HMAC)
- **Impacto:** posições em tempo real, zero chamadas HTTP para posições
- **Prioridade:** alta (elimina o gargalo na raiz)

### Otimização 4 — Debounce/reuso no frontend
- **Onde:** `gestao-cargas.js` → `carregarSubAbaAoVivo()`
- **O que fazer:** evitar re-chamar `verificarStatusCobli()` ao alternar sub-abas
- **Impacto:** elimina 1 chamada externa ao abrir a sub-aba pela segunda vez
- **Prioridade:** baixa

### Otimização 5 — Cache de `roadmap()`
- **Onde:** `CobliController::roadmap()`
- **O que fazer:** cachear o resultado por 60s (o roadmap não muda rápido)
- **Impacto:** reduz a chamada externa do `testarConexao()`
- **Prioridade:** baixa
